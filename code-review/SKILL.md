# Code review

Ревью — отдельный шаг, а не «посмотрел на код». Без него коммит не делается.

## When to use

- Перед каждым коммитом.
- После завершения фазы.
- Когда дифф затрагивает авторизацию, миграции, очереди, деньги, персональные данные, рассылки.

## Порядок

1. Собрать границы ревью: диапазон коммитов или список файлов.
2. **Проход 1 — критичное.** Безопасность, данные, гонки, потери, дубли.
3. Починить всё critical/high.
4. **Проход 2 — качество.** Имена, расположение, дубли, мёртвый код.
5. Починить то, что реально мешает читать и сопровождать.
6. Перезапустить тесты.
7. Записать отчёт в `.github/tasks/<slug>/review-N.md`.
8. Закоммитить правки **отдельным** коммитом.

## Проход 1: что искать

### Безопасность
- Проверка прав: текущий пользователь берётся из контекста, а не из параметра запроса.
- CSRF на всех изменяющих действиях.
- Экранирование вывода: `htmlspecialcharsbx`, а не сырая строка.
- Ссылки и изображения из внешних источников: разрешены только `/path` и `http(s)://`.
- SQL: нет конкатенации пользовательских значений; в raw-запросах — `forSql`.
- Секреты не попадают в логи, шаблоны, админку, ответы API.
- Чужие данные недоступны: выборки скоупятся по `user_id`.

### Данные и целостность
- Существующие миграции не изменены, только добавочные.
- Повторный запуск миграции/sync/агента безопасен.
- Уникальные ключи защищают от дублей там, где это заявлено.
- Удаление не приводит к повторной отправке или потере истории.

### Гонки и очереди
- Захват задач атомарный, есть lease и восстановление после падения.
- Статус меняется только из ожидаемого состояния.
- Отмена во время выполнения не перезаписывается успехом.
- Зависшие записи закрываются, а не висят вечно.

### Внешние системы
- «Поставили в очередь» ≠ «доставили».
- Неизвестный результат не повторяется вслепую.
- Ошибка внешней системы не роняет основной сценарий.

### Bitrix
- Namespace: `Bitrix\Main\ORM\Fields\ExpressionField`, а не `Bitrix\Main\Entity`.
- Сигнатура обработчика соответствует `VERSION` (1 — `&$fields`, 2 — `Event`).
- Компонент реализует `Controllerable`, action-методы имеют `configureActions()` с `Csrf`.
- Имя класса компонента уникально и наследует `CBitrixComponent`.
- Ассеты по путям, которые реально отдаются сервером.

### Шаблоны
- Нет `<?` вместо `<?php` в новом коде.
- Нет вывода без экранирования.
- Состояния пустоты, загрузки и ошибки предусмотрены.

## Проход 2: что искать

- God object, дублирование логики между классами.
- Мёртвый код, неиспользуемые параметры и атрибуты.
- Некорректные имена, не отражающие смысл.
- Файлы не на своём месте, нарушен namespace.
- Комментарии, повторяющие код.
- Лишние абстракции «на будущее», которые не используются сегодня.

## Шаблон отчёта

```markdown
# Ревью N — <фаза/скоуп>

Диапазон: `<sha>..<sha>` / список файлов

## Критичное
| # | Файл | Строка | Проблема | Серьёзность | Как исправлено |

## Качество
| # | Файл | Проблема | Решение |

## Проверено и признано корректным
- ...

## Тесты после правок
- unit: ...
- ручной сценарий: ...
```

## Правила

- Находка без сценария отказа — не находка. Писать «что сломается и при каких условиях».
- Не раздувать отчёт стилистикой: только то, что влияет на поведение или сопровождение.
- Если находок нет — так и написать, перечислив, что проверено.
- Ревью субагентом допустимо, но не отменяет собственной проверки. Сабагенту передавать список файлов и диапазоны строк: у него нет доступа к codebase-memory.
- Если сабагент не дал ответа за ~5 минут или сделал больше 40 вызовов без результата — остановить и провести ревью самому.
