# AGENTS.md — правила работы

> **Это источник истины.** Проекты-потребители читают этот файл как
> `.opencode/skills/AGENTS.md`; корневой `AGENTS.md` в проекте — только указатель
> сюда, собственных правил в нём нет. OpenCode читает корневой `AGENTS.md`
> автоматически, этот файл — по его указанию, поэтому прочитать его целиком нужно
> до начала любой задачи.
>
> При работе в самом репозитории `ai-agent-skills` действует служебный раздел в
> конце: команды и пути проекта RAD Aggregator здесь не выполняются.

Этот файл — **always-on** слой: короткие правила проекта RAD Aggregator, которые
действуют всегда. Подробные процедуры вынесены в скиллы `.opencode/skills/`.
Если задача попадает под триггер — сначала загрузи скилл, потом действуй.

## Приоритеты при конфликте

1. Явная команда пользователя в текущем сообщении.
2. Запреты из этого файла.
3. Скилл задачи.
4. Общие соглашения проекта.

Если правила противоречат друг другу — сказать об этом и предложить, какое оставить.

## Доступы и локальные данные

Любая задача, которой нужен вход на стенд (проверка интерфейса, PDF-инструкция,
ручной сценарий), начинается с поиска доступов — **не с вопроса пользователю**:

1. `.opencode/project-features.md` — какие переменные нужны, адрес стенда,
   ожидаемый id, чем именно входить в этом проекте. Локальный файл, в git не попадает.
2. `.opencode/.env.local` — значения переменных. Локальный, в git не попадает.
3. Нужной переменной нет ни там, ни там — **спросить у пользователя** одним вопросом,
   что именно нужно. Ответ дописать в `.env.local`, а не в код и не в скилл.

Правила:

- **Доступы не хардкодятся** ни в скиллах, ни в скриптах, ни в шаблонах, ни в `tasks.json`.
- Пароль не попадает в лог, отчёт, скриншот и текст инструкции.
- Способ входа зависит от платформы: для Bitrix — скилл `bitrix-login`, для других
  платформ — то, что написано в `project-features.md`. Универсального входа нет.
- Не подбирать пароли, не пробовать чужие учётки, не заводить нового пользователя.

## Поиск по коду: сначала codebase-memory

Любой поиск по коду — **сначала codebase-memory** (`search_graph`, `trace_path`,
`get_code_snippet`), grep — только фолбэк. Правило действует на меня и на субагентов,
и применяется **к каждому новому вопросу**, а не один раз за задачу: если grep уже
пригодился, следующий вопрос всё равно начинается с графа.

- В индексе есть `project/src`, `project/tests`, `project/config`, `project/services`.
- **`project/public/**` (компоненты, модули, шаблоны, админки Bitrix) в индексе нет** —
  для этих путей grep законен сразу.
- Read-only субагентам граф недоступен: правило передаётся в промпте словами.
- Индексировать — только при пуше и только с подтверждения.

Детали — в скилле `codebase-memory`.

## Обязательный цикл задачи

Любая задача крупнее одного шага проходит:

```
план → фаза → реализация → ревью → правки → тесты → коммит → следующая фаза
```

- План и артефакты — в `.opencode/tasks/<slug>/`.
- Документация фичи для людей — в `.opencode/docs/`.
- Своя память и заметки — только в `.opencode/`, нигде больше.
- «Тесты прошли» не заменяет ревью. Ревью не заменяет тесты.
- Не переходить к следующей фазе, пока текущая не зелёная.

## Незыблемые запреты

- **Не пушить без подтверждения.** Ветки `stage` и `dev` — никогда.
- **Не индексировать codebase-memory без подтверждения.** Только при пуше.
- **Не править** `local/templates/*/static/**` (`main.css`, `main.js` и прочее). Свои стили — в `style.css` компонента.
- **Не изменять существующие миграции.** Только добавочные.
- **Не писать секреты** в код, логи, шаблоны, админку и ответы API. Доступы для тестов — только `.opencode/.env.local`.
- **Не выполнять destructive-команды** (`rm -rf`, `DROP`, force-push) без явной просьбы.
- **Не зависать в ожидании субагента.** Нет результата за ~5 минут или больше 40 вызовов без ответа — остановить и сделать самому.
- **Не коммитить временные файлы**: страницы входа, дампы, скрипты проверок вне `.opencode/tests`.

## Код

- Комментарии — на английском, кратко, только там, где имя не раскрывает смысл.
- Русский — в текстах интерфейса и сообщениях пользователю.
- Повторный запуск миграций, sync-команд и агентов должен быть безопасным.
- Bitrix D7 и ORM; `Bitrix\Main\ORM\Fields\*`, а не `Bitrix\Main\Entity\*`.

## Тесты

- Unit — на новую логику, в `project/tests/`.
- Ручной сценарий — в `project/.opencode/tests/<slug>/`.
- UI — через `playwright-mcp`, артефакты в `.opencode/playwright-mcp`.
- Результаты прогонов и ревью — в папку задачи.

## Субагенты

- Один субагент — одна узкая задача с критерием остановки.
- Read-only субагентам (`code-review`, `explore`) недоступен codebase-memory: передавать им файлы и диапазоны строк.
- В каждый промпт поисковому субагенту писать правило: **сначала codebase-memory, grep только если пусто**; `project/public/**` в индексе нет — там сразу grep.
- Не поручать субагенту «понять весь проект» — только конкретный вопрос.

## Служебный раздел: работа в репозитории скиллов

> Этот раздел нужен только при работе в самом репозитории `ai-agent-skills`.
> В проекте-потребителе его можно игнорировать.

Репозиторий — источник скиллов, а не приложение: `make aggregator-test-*` и пути
`project/` здесь не работают, браузерные проверки не запускаются. Подробности —
в `README.md` и скилле `skill-maintenance`.

- В этом репозитории скиллы лежат в корне (`<name>/SKILL.md`); в проекте-потребителе
  этот репозиторий подключён как `.opencode/skills`. Пути в правилах выше — для проекта.
- Править скиллы только здесь. `.opencode/skills` в проекте — checkout этого
  репозитория: правка там теряется при обновлении и попадает в чужой проект.
- Новый скилл — папка `<name>/SKILL.md`: `name` — display name (ID в OpenCode
  берётся из имени папки, поэтому держите их совпадающими), `description` — одна
  строка в одинарных кавычках с триггерами «Use when …». Добавить строку в таблицу
  состава `README.md` и в «Карту скиллов» выше, иначе скилл не считается подключённым.
- Скрипты — `<name>/scripts/`, эталоны — `<name>/example/`. `templates/`, `tools/`,
  `example/` скиллами не являются (`SKILL.md` там нет).
- Исполняемое проверять запуском: `bash -n tools/skills.sh`,
  `node --check pdf-instructions/scripts/shot.mjs`, затем реальный прогон. После
  рефакторинга чаще всего ломаются пути и имена переменных в тексте скиллов.
- PDF-пайплайну нужны Chrome (`CHROME_BIN`, иначе `/Applications/Google Chrome.app`)
  и Python-пакеты `PyMuPDF` (`fitz`), `Pillow`, `pypdf`; манифеста зависимостей нет.
- Перед коммитом: `grep -rniE "password|пароль" --include=SKILL.md .` — только
  описания, не значения; `git status --ignored` — `.env*` и `project-features.md`
  должны быть в игноре; в диффе нет скриншотов с личными данными.
- Сообщение коммита — английское, императив, до ~72 символов.
- После коммита не пушить сразу: спросить разрешение, затем `git push origin main`
  и `tools/skills.sh update`. Указатель сабмодуля `.opencode/skills` в проекте
  коммитится отдельно, тоже по подтверждению.
